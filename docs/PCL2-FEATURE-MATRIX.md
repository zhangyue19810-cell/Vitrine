# Vitrine 与 PCL2 的功能对照

Vitrine 是独立实现的：没有使用 PCL2 的任何源代码，只是对照 PCL2 公开的功能清单做了功能对标，并使用与 PCL2
相同的官方源与镜像源（Mojang / Forge / NeoForge / Fabric / Quilt / Modrinth / CurseForge 官方地址，以及
BMCLAPI、MCIM 两个镜像）。

**结论先说：没有做到 PCL2 的“全部功能”。** 启动、安装、下载、整合包、模组 / 存档 / 服务器管理这些核心流程已经覆盖，
并有自动化测试；个性化（自定义背景 / 音乐 / 主页）、联机、皮肤更换、中文名翻译、自动更新等没有做。下面逐项列出。

图例：✅ 已实现并有测试覆盖　🟡 部分实现（说明里写明差在哪）　⬜ 没有实现

> “已实现”指后端逻辑在 217 项自动化测试里跑通（本地 mock 服务器，不联网），界面在浏览器 + Electron（Linux）里点过。
> 还没有在真实 Windows 机器上长期使用过，也没有用真实的 Mojang / 镜像服务器做过全量回归。

| 导出启动脚本 | ✅ | `.bat` / `.sh`，可选是否写入登录令牌（默认不写） |

| 崩溃分析 | 🟡 | 19 类规则：Java 过旧 / 过新、内存不足、JVM 参数错误、缺少前置模组、模组与游戏版本不符、重复模组、Mixin 失败、类链接错误、OpenGL 问题、JVM 崩溃、损坏的 jar、找不到主类、配置文件错误、磁盘已满、文件被占用、登录会话失效、实体 / 方块实体 tick 崩溃。多数带建议操作（调内存、换 Java、修复文件、一键补齐前置、去重、重置 JVM 参数…）。规则库比 PCL2 小，没有“导出崩溃报告压缩包” |

## 已知限制

- Windows 上命令行超过 30 000 字符才会用 `@argfile`；这时如果路径里有非 ASCII 字符（例如中文用户名），argfile 的编码问题可能让 Java 找不到文件。普通整合包的命令行达不到这个长度。
- 服务器列表的在线检测在网络错误时会显示原始错误文本，没有翻译成更友好的说法。
- 崩溃分析的规则库有限，没覆盖到的崩溃只会给出通用建议。
- 没有代码签名证书：首次运行 Windows SmartScreen 可能拦截。
